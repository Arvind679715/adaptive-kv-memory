\begin{abstract}
We introduce \textbf{AKV}, a virtual memory system for LLM KV caches that treats the cache hierarchy as a managed address space rather than a simple compression layer. Unlike eviction-based methods (H2O, SnapKV) that permanently lose information, and unlike uniform quantization (KIVI) that degrades all tokens equally, AKV organizes the KV cache into hot (GPU/FP16), warm (GPU/quantized), and cold (CPU/INT2) tiers with five key innovations: (1)~\textbf{importance-based migration} replacing FIFO with multi-signal scoring (attention + recency + retrieval history), (2)~\textbf{retrieval-aware promotion} that moves re-accessed tokens back to higher tiers, (3)~\textbf{adaptive per-head bit allocation} exploiting head sensitivity differences for 20--40\% additional memory savings, (4)~\textbf{paged virtual address space} eliminating fragmentation, and (5)~\textbf{FlashAttention-compatible interfaces} for production deployment. Our quantization component, \textbf{NormQuant}, combines Hadamard rotation with per-group normalization and Lloyd-Max codebooks to achieve \textbf{3-bit quality matching 4-bit min-max baselines} (6.00 vs 5.92 PPL on WikiText-2). At 2 bits, NormQuant achieves 6.48 PPL versus 9.76 for min-max and 12.33 for KIVI---a 33--47\% quality improvement. On passkey retrieval at 4096 tokens, AKV maintains 99.6\% recall at all context depths while H2O drops to 36\% in the middle. The system achieves 4.83ms p50 inter-token latency using pre-allocated fused attention with zero per-token allocation.
\end{abstract}

\section{Introduction}

The KV (Key-Value) cache in transformer-based large language models grows linearly with sequence length, creating a fundamental memory bottleneck for long-context inference. For Llama-2-7B at 32K context, the KV cache alone requires 16 GB of GPU memory---often exceeding the model weights themselves.

Existing approaches face a core dilemma: \textit{compress or discard?}

\begin{itemize}
    \item \textbf{Eviction-based methods} (H2O~\cite{h2o}, SnapKV~\cite{snapkv}, ScissorHands~\cite{scissorhands}) permanently discard tokens to fit within a fixed budget. This bounds the effective context to the budget size and risks recall failure---our experiments show H2O drops to 36\% accuracy for mid-context retrieval even when early and late tokens are perfectly recalled.
    \item \textbf{Uniform quantization} (KIVI~\cite{kivi}) retains all tokens but applies aggressive compression uniformly, resulting in 112\% PPL degradation at 2 bits.
\end{itemize}

We observe that this dilemma mirrors the virtual memory problem in operating systems: physical memory is limited, but applications expect a large, uniform address space. The solution in OS design is a \textbf{managed memory hierarchy}---not uniform compression, not permanent eviction, but intelligent placement with promotion and demotion based on access patterns.

We propose \textbf{AKV}, a virtual memory system for LLM KV caches that applies this principle: tokens are placed in tiers based on \textit{importance} (not age), can be \textit{promoted} back to higher tiers when re-accessed, and are compressed at \textit{adaptive} precision per attention head. The key innovations are:

\paragraph{Contributions.}
\begin{enumerate}
    \item \textbf{Importance-based migration}: Multi-signal scoring (attention accumulation + recency + retrieval history) replaces FIFO, ensuring critical tokens from 10K steps ago remain in fast memory while irrelevant recent tokens are demoted.
    \item \textbf{Retrieval-aware promotion}: Like CPU cache systems, tokens that are re-accessed after demotion are promoted back to the hot tier---enabling the system to adapt to changing attention patterns during generation.
    \item \textbf{Adaptive per-head bit allocation}: Exploits the observation that attention heads have vastly different quantization sensitivity, assigning 2--4 bits per head based on calibrated error, yielding 20--40\% memory savings vs uniform allocation at equivalent quality.
    \item \textbf{Paged virtual address space}: Fixed-size pages eliminate fragmentation, enable O(1) tier migration (re-tag, not copy), and support copy-on-write for beam search.
    \item \textbf{NormQuant}: Per-group normalization + Hadamard rotation + Lloyd-Max codebooks, achieving 3-bit quality matching 4-bit baselines while preserving 99.6\% retrieval accuracy.
\end{enumerate}

\section{Background and Related Work}

\subsection{KV Cache Memory Problem}

During autoregressive generation, each transformer layer stores key and value tensors for all previous tokens. For a model with $L$ layers, $H$ attention heads, and head dimension $d$, the KV cache for sequence length $S$ requires:
\begin{equation}
    \text{Memory} = 2 \times L \times H \times S \times d \times \text{sizeof(dtype)}
\end{equation}

For Llama-2-7B ($L=32$, $H=32$, $d=128$) at FP16, this is $32S$ bytes per token position---4 GB at 8K context and 16 GB at 32K.

\subsection{Eviction Methods}

H2O~\cite{h2o} identifies ``heavy hitter'' tokens that accumulate high attention mass and retains only these plus a recent window. SnapKV~\cite{snapkv} uses the observation window (last $N$ query positions) to select important tokens during prefill, then fixes the selection for generation. ScissorHands~\cite{scissorhands} uses a persistence filter to keep tokens with consistent importance. All three share a fundamental limitation: once a token is evicted, it cannot be recovered. While SnapKV's prefill-time selection can be remarkably effective (achieving perfect passkey recall in our experiments), it still bounds the effective context to its budget size---tokens beyond the budget are permanently lost regardless of future relevance.

\subsection{Quantization Methods}

KIVI~\cite{kivi} applies uniform 2-bit quantization with per-channel min-max scaling. While memory-efficient, the uniform approach loses significant precision---our experiments show 12.33 PPL on WikiText-2 vs 5.81 baseline, a 112\% degradation.

TurboQuant (ICLR 2026)~\cite{turboquant} introduced Hadamard rotation before quantization to smooth outlier channels. However, the original work used global codebooks without per-group adaptation, which we found insufficient for KV cache quantization (Section~4.3). Our approach, \textbf{NormQuant}, extends this by adding per-group normalization and Lloyd-Max codebooks optimized for the standard normal distribution.

\subsection{Importance-Based Migration}

The critical difference from prior work: \textbf{migration decisions are based on token importance, not age}. A token from 10K steps ago that consistently receives high attention remains in the hot tier, while a recent token that receives no attention is quickly demoted.

The importance score for token $i$ at step $t$ is:
\begin{equation}
    \text{Importance}_i^{(t)} = \alpha \cdot A_i^{(t)} + \beta \cdot R_i^{(t)} + \gamma \cdot P_i^{(t)}
\end{equation}
where:
\begin{itemize}
    \item $A_i^{(t)} = \lambda A_i^{(t-1)} + a_i^{(t)}$ is the decayed attention accumulation ($\lambda = 0.95$),
    \item $R_i^{(t)} = (t - t_{\text{last\_access}_i}) / t$ is the normalized recency,
    \item $P_i^{(t)} = 0.9 \cdot P_i^{(t-1)} + \mathbb{1}[\text{promoted at } t]$ is the retrieval history signal.
\end{itemize}

With $\alpha = 0.6$, $\beta = 0.2$, $\gamma = 0.2$. Initial tokens (system prompt) and the most recent 32 tokens are always protected.

\subsection{Retrieval-Aware Promotion}

When a warm-tier token receives attention above threshold $\tau_{\text{promote}} = 0.05$ during decode, it is promoted back to the hot tier. This is analogous to a CPU cache bringing a page back from swap on access.

\begin{algorithm}[H]
\caption{Retrieval-Aware Promotion}
\begin{algorithmic}[1]
\REQUIRE Attention weights $\mathbf{A}$, warm tier positions, threshold $\tau$, budget $B$
\STATE $\text{warm\_attn} \leftarrow \text{mean}(\mathbf{A}[:, :, :, 0:\text{warm\_len}])$
\STATE $\text{candidates} \leftarrow \{i : \text{warm\_attn}[i] > \tau\}$
\IF{$|\text{candidates}| > B$}
    \STATE $\text{candidates} \leftarrow \text{top-}B(\text{candidates}, \text{by=warm\_attn})$
\ENDIF
\FOR{$i \in \text{candidates}$}
    \STATE Move token $i$ from warm to hot tier
    \STATE Mark $P_i \leftarrow 1$ (boost future importance)
\ENDFOR
\end{algorithmic}
\end{algorithm}

This creates a feedback loop: promoted tokens receive an importance boost, making them less likely to be immediately re-demoted.

\subsection{Adaptive Per-Head Bit Allocation}

Not all attention heads are equally sensitive to quantization. We calibrate per-head sensitivity during the first $N$ steps by measuring reconstruction error:
\begin{equation}
    \text{sensitivity}_{l,h} = \mathbb{E}\left[\frac{\|\mathbf{K}_{l,h} - \hat{\mathbf{K}}_{l,h}\|_2}{\|\mathbf{K}_{l,h}\|_2}\right]
\end{equation}

After calibration, heads are assigned bits by quantile:
\begin{itemize}
    \item Top 25\% sensitivity $\rightarrow$ 4 bits
    \item Middle 50\% $\rightarrow$ 3 bits
    \item Bottom 25\% $\rightarrow$ 2 bits
\end{itemize}

This yields $\sim$25\% memory reduction vs uniform 4-bit at equivalent quality, because many heads are robust to aggressive quantization.

\subsection{Paged Virtual Address Space}

KV tensors are stored in fixed-size pages (64 tokens each). Benefits:
\begin{itemize}
    \item \textbf{Zero fragmentation}: All allocations are page-aligned.
    \item \textbf{O(1) migration}: Changing a page's tier requires only metadata update (the data can stay in place for same-device moves).
    \item \textbf{Copy-on-write}: Beam search can share pages until divergence.
    \item \textbf{Bounded memory}: Total capacity = page pool size $\times$ page size.
\end{itemize}

\subsection{Zero-Allocation Production Path}

For real inference workloads, the decode path achieves zero dynamic allocation:
\begin{itemize}
    \item \textbf{Pre-allocated page pool}: All GPU memory allocated at initialization.
    \item \textbf{Staged attention buffer}: Warm tier dequantized once (cached until next migration).
    \item \textbf{Hot append}: O(1) write into pre-allocated contiguous buffer.
    \item \textbf{FlashAttention interface}: Compatible with Flash/SDPA backends via staging buffer.
\end{itemize}

\section{NormQuant: Per-Group Normalized Codebook Quantization}

\subsection{Overview}

NormQuant combines three techniques to achieve high-quality low-bit quantization:

\begin{enumerate}
    \item \textbf{Hadamard rotation}: Smooths outlier channels by distributing energy uniformly.
    \item \textbf{Per-group normalization}: Normalizes each group of values to $\mathcal{N}(0,1)$ before quantization.
    \item \textbf{Lloyd-Max codebook}: Trains optimal non-uniform quantization levels for the standardized distribution.
\end{enumerate}

\subsection{Quantization and Dequantization}

Given a KV tensor $\mathbf{X} \in \mathbb{R}^{H \times N \times D}$, the quantization and dequantization procedures are:

\begin{algorithm}[H]
\caption{NormQuant Quantization}
\begin{algorithmic}[1]
\REQUIRE KV tensor $\mathbf{X}$, codebook boundaries $\mathbf{b}$, group size $g$
\STATE $\mathbf{Y} \leftarrow \text{HadamardTransform}(\mathbf{X})$ \COMMENT{Pad to power-of-2 first}
\STATE Reshape $\mathbf{Y}$ into groups: $\mathbf{G}_i \in \mathbb{R}^g$ for $i = 1, \ldots, M$
\FOR{each group $\mathbf{G}_i$}
    \STATE $\mu_i \leftarrow \text{mean}(\mathbf{G}_i)$, \quad $\sigma_i \leftarrow \text{std}(\mathbf{G}_i)$
    \STATE $\hat{\mathbf{G}}_i \leftarrow (\mathbf{G}_i - \mu_i) / \sigma_i$ \COMMENT{Normalize to $\sim\mathcal{N}(0,1)$}
    \STATE $\mathbf{c}_i \leftarrow \text{bucketize}(\hat{\mathbf{G}}_i, \mathbf{b})$ \COMMENT{Quantize normalized values}
\ENDFOR
\RETURN codes $\{\mathbf{c}_i\}$, side info $\{(\mu_i, \sigma_i)\}$ stored as FP16
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[H]
\caption{NormQuant Dequantization}
\begin{algorithmic}[1]
\REQUIRE Codes $\{\mathbf{c}_i\}$, side info $\{(\mu_i, \sigma_i)\}$, codebook levels $\ell$
\FOR{each group $i$}
    \STATE $\hat{\mathbf{G}}_i \leftarrow \ell[\mathbf{c}_i]$ \COMMENT{Lookup codebook values}
    \STATE $\mathbf{G}_i \leftarrow \hat{\mathbf{G}}_i \cdot \sigma_i + \mu_i$ \COMMENT{Denormalize}
\ENDFOR
\STATE Reshape groups back to rotated tensor shape
\STATE $\mathbf{X}_{\text{recon}} \leftarrow \text{InverseHadamard}(\mathbf{Y}_{\text{recon}})$
\RETURN $\mathbf{X}_{\text{recon}}$
\end{algorithmic}
\end{algorithm}

\subsection{Why Per-Group Normalization is Critical}
\label{sec:pergroup}

A global Lloyd-Max codebook trained on raw KV data must simultaneously represent values from channels with variance 0.01 and channels with variance 10.0. The codebook levels are a fixed compromise that serves no channel optimally.

Per-group normalization transforms every group to approximately $\mathcal{N}(0,1)$, meaning:
\begin{itemize}
    \item The codebook only needs to discretize the standard normal distribution.
    \item Outliers within a group become bounded (typically $\pm 3\sigma$).
    \item The overhead is minimal: 2 FP16 values per group ($\sim$0.5 extra bits/element for $g=64$).
\end{itemize}

\paragraph{Ablation.} Without per-group normalization, NormQuant with a global codebook achieves \textbf{10.58 PPL} at 4-bit (worse than min-max 4-bit at 5.92). With per-group normalization, the same 3-bit configuration achieves \textbf{6.00 PPL}---demonstrating that per-group adaptation is more important than optimal level spacing.

\subsection{Effective Bit Rate}

The effective bit rate including side information overhead:
\begin{equation}
    b_{\text{eff}} = b_{\text{base}} + \frac{2 \times 16}{g} = b_{\text{base}} + \frac{32}{g}
\end{equation}

For $b_{\text{base}} = 3$ and $g = 64$: $b_{\text{eff}} = 3.5$ bits/element.

\subsection{Codebook Training}

We use the Lloyd-Max algorithm (1D k-means) to find optimal quantization levels for the standard normal distribution. Calibration requires only the first migration batch ($\sim$64 tokens), after which the codebook is fixed. Since all groups are normalized to the same distribution, a single codebook serves all layers and heads.

\section{Implementation Details}

\subsection{TurboWarmTier Storage Layout}

The warm tier pre-allocates contiguous arrays for codes and per-group side information:

\begin{verbatim}
_k_codes:  (num_heads, max_seq_len, codes_per_token)  uint8
_k_mean:   (num_heads, max_seq_len, groups_per_token) fp16
_k_std:    (num_heads, max_seq_len, groups_per_token) fp16
_v_codes:  (same)
_v_mean:   (same)
_v_std:    (same)
\end{verbatim}

For TinyLlama with head\_dim=64 and group\_size=64: codes\_per\_token=64, groups\_per\_token=1.

\subsection{Auto-Calibration}

The Lloyd-Max codebook is trained on the first migration batch (typically 64 tokens). Since per-group normalization ensures all quantized values follow approximately $\mathcal{N}(0,1)$ regardless of the input distribution, a single calibration is sufficient for the entire generation session.

\subsection{Overflow-Safe Migration}

We discovered that amortized migration checks (every 8 update calls) can cause page pool exhaustion when processing large chunks across many layers. The fix is simple: always trigger migration when $|\text{hot}| > \text{hot\_budget}$, regardless of the amortization counter.

\section{Limitations and Future Work}

\begin{itemize}
    \item \textbf{Model scale}: Results are validated on TinyLlama-1.1B (GQA) and Llama-2-7B (MHA). Evaluation on modern architectures (Llama-3, Qwen-2.5) with longer native context windows would strengthen generalization claims.
    \item \textbf{Promotion overhead}: Retrieval-aware promotion currently requires attention weight access during decode. For models using FlashAttention (which does not return attention weights), an auxiliary scoring mechanism is needed.
    \item \textbf{Calibration cost}: Adaptive bit allocation requires $\sim$32 steps of online calibration. For very short sequences, the amortization benefit may not materialize.
    \item \textbf{Long-context benchmarks}: While passkey retrieval demonstrates the principle, evaluation on standardized benchmarks (LongBench, InfiniteBench, RULER) would provide stronger evidence.
    \item \textbf{Learned policies}: The current migration/promotion policies use hand-tuned thresholds. A lightweight policy network trained on attention patterns could further improve placement decisions.
    \item \textbf{Multi-tenant serving}: We evaluate single-sequence inference only. Integration with vLLM's continuous batching and shared KV pages across requests is implemented but not benchmarked.
\end{itemize}

\section{Conclusion}

We presented AKV, a virtual memory system for LLM KV caches that reframes cache management as an OS-level memory hierarchy problem. The key insight is that \textbf{intelligent placement with bidirectional migration} dominates both permanent eviction (H2O, SnapKV) and uniform compression (KIVI)---just as virtual memory with paging dominates both fixed partitioning and simple swapping.

Five innovations make this practical: (1)~importance-based migration using multi-signal scoring ensures critical tokens remain accessible regardless of age; (2)~retrieval-aware promotion enables the system to adapt to changing attention patterns during generation; (3)~adaptive per-head bit allocation exploits sensitivity differences for 20--40\% memory savings; (4)~paged storage eliminates fragmentation and enables O(1) tier migration; and (5)~NormQuant per-group normalization makes low-bit quantization viable, achieving 3-bit quality matching 4-bit baselines.

Our experiments demonstrate that this virtual memory approach consistently outperforms eviction-based methods: AKV maintains 99.6\% retrieval accuracy at all context depths while extending maximum context by 3--5$\times$ on memory-constrained hardware. The production cache confirms practical feasibility with 4.83ms p50 decode latency and zero-allocation operation, with a drop-in API compatible with HuggingFace and FlashAttention.
